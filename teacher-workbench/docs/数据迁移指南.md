# 数据迁移指南（迁入英语教师教学工作台）

本文档面向需要把**现有教学数据迁入本平台**的学校/机构技术人员，以及负责执行迁入的**平台管理员**。

## 1. 平台存储架构

| 存储 | 用途 | 迁移方式 |
|---|---|---|
| Cloudflare D1（SQLite） | 全部结构化数据：租户、班级、学生、教案、课表、作业、默写、考试等 | **JSON 文件迁入**（本文档主体） |
| Cloudflare R2（对象存储） | 文件本体：默写材料、试卷、教案附件等 | 不随 JSON 迁移，见 §6 |

## 2. 迁移载体：version 3 备份 JSON

迁入文件的格式与平台「数据管理 → 导出全部数据」生成的备份**完全一致**，顶层结构：

```json
{
  "version": 3,
  "tenant": { "id": "...", "name": "学校名称", "slug": "...", "type": "organization", ... },
  "classes": [],
  "students": [],
  "lessons": [],
  "schedules": [],
  "assignments": [],
  "submissions": [],
  "dictations": [],
  "dictationResults": [],
  "exams": [],
  "scores": [],
  "subscores": []
}
```

- `version` 必须为整数 `3`，否则迁入被拒绝。
- 各数组的**字段名就是数据库列名（snake_case）**，字段即 `SELECT *` 的原始行。
- `tenant` 块在迁入时仅作参考（展示用），目标租户由迁入入口另行选择/新建。
- 所有时间戳为 ISO 8601 字符串（`new Date().toISOString()`），如 `2026-09-11T08:00:00.000Z`。
- 所有 `id` 为 UUID 文本。迁入时**保留原 id**（便于关联），同一租户内不可重复。

## 5. 迁入操作（平台管理员）

1. 登录平台，进入左侧「平台管理」页，找到**数据迁入**板块（仅平台管理员可见）。
2. 选择导入方式：
   - **覆盖导入**（缺省）：先清空目标空间 11 张业务表，再整体写入备份。适合首次迁入。
   - **增量导入（合并匹配）**：不动现有数据，把备份**合并**进目标空间（见 §5.1 匹配规则）。适合二次迁入、多源合并。
3. 选择目标：迁入**已有租户**（下拉选择学校空间），或**新建租户**（填写学校名称，自动创建空间并把你设为所有者）。
4. 选择按本文档准备好的 `.json` 文件（也可在板块内点击「下载迁移模板」获取空骨架）。
5. 点击「开始迁入」，页面显示结果（各表条数；增量模式额外显示匹配到的班级/学生数）。
6. 失败会给出具体错误（版本不符、JSON 损坏、行缺必填列等）。

### 5.1 增量导入匹配规则（全部落到空间真实 id）

| 对象 | 匹配键 | 命中时 | 未命中时 |
|---|---|---|---|
| 班级 | `name` + `academic_year` | 复用真实班级 id，就地更新名称/年级/毕业年份，**保留现有班主任** | 新建（id 用备份 id；班主任归导入者） |
| 学生 | `student_no`（无学号按 `name`+班级） | 复用真实学生 id，就地更新姓名/性别等，**挂到真实班级** | 新建并挂到（重映射后的）真实班级 |
| 老师 | `teacherMap`（可选，备份里的旧 userId → 本空间成员 userId） | 教案/作业/默写/考试的创建者按映射归属 | 归导入操作者 |
| 子表（提交/默写结果/成绩/小分） | 随父表 id | 其 `student_id`/`class_id` 一律重映射到匹配后的真实 id | 同左（指向新建行） |

- 增量模式写入用 `INSERT OR REPLACE`，**同一备份重复导入结果不变**（幂等，不膨胀）。
- 所有行的 `tenant_id` 强制改写为目标空间（两种模式一致）。

## 6. 不在 JSON 迁移范围内的数据

| 数据 | 处理方式 |
|---|---|
| 用户账号与成员关系（memberships）、班级任课老师（class_teachers）、年级组（grade_groups / grade_group_prep_leaders） | 不随备份迁移。迁入完成后由租户管理员在平台内邀请成员、设置班主任/任课老师/年级组 |
| 回收站（recycle_bin） | 平台功能，删除记录保留 30 天自动清理，不迁移 |
| 教案附件关联（lesson_files） | 附件关系不迁移；文件本体处理见下一行，迁入后在平台内重新关联 |
| 租户配额、到期时间、教师权限开关（user_permissions）、按用户配额（user_quotas） | 迁入后在平台管理页另行设置 |
| R2 文件本体（默写材料/试卷/教案附件） | JSON 只带 `material_url`/`paper_url` 文本链接。若原文件在旧平台，需先把文件上传到本平台的 R2（例如经由任一租户的文件上传入口），再把返回的公共 URL 填进 JSON 对应字段；或迁入后在平台内重新上传并更新链接 |
| AI 使用记录、审计日志 | 系统生成，不迁移 |
| 上一学年压缩归档（year_archives） | 平台自动管理，不迁移 |

## 7. 限制与注意事项

- **覆盖式迁入**：覆盖导入会清空目标租户 11 张业务表再写入，执行前请确认目标空间，并提醒学校先自行导出备份；增量导入不清空，但同 id 行会被备份内容替换。
- **一致性**：`class_id`/`student_id`/`assignment_id`/`dictation_id`/`exam_id` 必须指向同一 JSON 文件内的行；指向不存在的行会在使用时表现为缺失（迁入本身不做外键校验，请自行保证）。
- **批量处理**：D1 每批最多提交 1000 条语句，迁入/恢复会自动分批；临时失败的批次最多自动重试 3 次。多批次过程中若持续失败，接口会返回失败批次，需在确认数据状态后重试。
- **文件大小**：迁入 JSON 请求体上限 50MB。
- **幂等与重复**：覆盖模式同一文件重复迁入 = 再次覆盖；增量模式同备份重复导入结果不变（按 id 幂等）。

## 8. 附录：给 AI 助手的数据存储说明（机器可读）

> 本附录供 AI 编程/数据助手阅读，帮助学校把现有数据（Excel 名单、成绩表、旧系统等）转换为上文定义的 version 3 迁移 JSON。**如果你正在使用 AI 辅助迁移，请把本文档（尤其 §2/§3/本附录）整体提供给 AI。**

### 8.1 全局存储模型（必须先理解的 7 条规则）

1. **多租户隔离**：所有业务数据按 `tenant_id`（学校空间）隔离；迁入时 `tenant_id` 由平台强制改写为目标空间，JSON 里写什么值都会被覆盖，但每行仍必须带该键。
2. **学年制**：学年格式 `YYYY-YYYY`，9 月 1 日切换（东八区）。`classes`/`students`/`lessons`/`schedules`/`assignments`/`dictations`/`exams` 都带 `academic_year`；默写/作业/考试的**子表**（results/submissions/scores/subscores）不带学年，学年通过父表条目传递。
3. **ID 即关联**：表间关联全部用 UUID 文本（`class_id`→`classes.id`、`student_id`→`students.id`、`assignment_id`→`assignments.id`、`dictation_id`→`dictations.id`、`exam_id`→`exams.id`）。迁入保留原 id，因此**必须先为每个班级/学生生成稳定 UUID，再填充引用**。
4. **时间格式**：所有 `created_at`/`updated_at`/`submitted_at` 等是 ISO 8601 字符串（`new Date().toISOString()`），不是 Unix 时间戳。
5. **布尔即整数**：`passed`/`retest_required`/`retest_completed` 等是 INTEGER，`1`=真、`0`=假。
6. **可空列**：源数据没有的列（`gender`/`notes`/`student_no`/`deadline` 等）写 `null` 或省略，但不要 invent 假值。
7. **两种导入模式**：覆盖导入 = 清空目标空间 11 张业务表后整体写入（首次迁入）；增量导入 = 合并匹配——班级按名称+学年、学生按学号匹配空间已有记录并就地更新，子表挂到匹配后的真实班级/学生/老师（二次迁入）。迁移 JSON 的写法两种模式相同。

### 8.2 实体关系（文本 ER）

```text
tenant(学校空间) 1─n classes(班级)        关键列: name, grade, academic_year, graduation_year
tenant           1─n students(学生)       关键列: class_id→classes, student_no, name, academic_year
classes          1─n assignments(作业)    关键列: class_id, title, deadline, academic_year
assignments      1─n [submissions](提交)  键名 submissions; 关键列: assignment_id, student_id, status(submitted/pending/missing), submitted_at
classes/dictations: dictations(默写)      关键列: title, scope(class/grade), class_id(可空), dictation_date, academic_year
dictations       1─n [dictationResults]  键名 dictationResults; 关键列: dictation_id, student_id, passed, retest_required, retest_completed
exams(考试)      1─n [scores](成绩)       键名 scores; 关键列: exam_id, student_id, score(REAL,可空)
exams            1─n [subscores](小分)    键名 subscores; 关键列: exam_id, student_id, question_type, score, max_score
lessons(教案)    独立                    关键列: title, lesson_type, content(Markdown), status, academic_year(=创建学年)
schedules(课表)  独立                    关键列: weekday(1-7), period, start_time/end_time, title, class_id(可空=全年段)
```

scope 语义：`scope='grade'` 表示全年段（年级组/管理员发布，class_id 为空），其 results/scores 覆盖全年级所有学生；`scope='class'` 表示仅本班。

### 8.3 典型转换配方（源数据 → 迁移 JSON）

**A. 一个 Excel 工作簿，每班一个 sheet（学生名单）**
1. 遍历 sheet 名 → 在 `classes` 建行（`name`=sheet 名，`grade` 从 sheet 名或表头推断，`academic_year`=目标学年）。
2. 每个 sheet 的数据行 → `students` 行（`class_id`=上一步 UUID，`student_no`/`name`/`gender` 按列映射）。
3. 学生按 `student_no` 排序生成，保证可重复执行。

**B. 一张成绩总表（行=学生，列=考试名）**
1. 每个列（考试）→ `exams` 行（`scope='grade'`、`academic_year`=考试所在学年；考试日期从列名解析）。
2. 每格分数 → `scores` 行（`exam_id`+`student_id` 双关联）；空格/缺考 → `score: null`（不生成行亦可）。
3. 若成绩表按题型分列（如「听力 30」），每题型的分数 → `subscores` 行（`question_type`=题型，`max_score`=满分）。

**C. 作业/默写登记表（行=学生，列=日期或项目）**
1. 列 → `assignments`/`dictations` 行；格子值（√/×/P/F/分数）→ `submissions`（`status`）或 `dictationResults`（`passed`/`retest_required`）。
2. 「需重默」标记 → `retest_required=1` 且 `retest_completed=0`。

### 8.5 常见错误（AI 转换高频踩坑）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用行号/自增数字当 id 或关联键 | 关联断裂、重复迁入冲突 | 一律 UUID，且全局唯一 |
| 忘记 `tenant_id` 列 | 迁入报错（列缺失） | 每行都带，值随意（会被改写） |
| `created_at` 写 `2026-09-01` 或时间戳数字 | 排序/显示异常 | ISO 8601：`2026-09-01T00:00:00.000Z` |
| 布尔写 `true/false` 或「是/否」 | 统计全错 | INTEGER `1`/`0` |
| 缺考的格子写 0 分 | 与真实 0 分混淆 | `score: null`（缺考）与 0（得零分）区分 |
| 全年段考试填了 `class_id` | 成绩归属错误 | `scope='grade'` 时 `class_id` 为 null |
| 学生换班后只改名单不改历史 | 历史归属错乱 | 历史结果行保留原 `class_id` 语义：结果只认 student_id，班级由学生当前归属解释 |

## 9. 新功能数据口径与导入指标（2026-09 修订）

> 平台迭代后的新功能对迁入数据的影响与指标口径。迁移 JSON 的 13 键结构不变，本节字段已并入 §3 各表。

### 9.1 成绩导入自动识别（界面导入指标）

迁入后老师在「考试成绩 → 导入成绩 / 导入小分」上传文件时，平台**自动识别**以下两种常见格式（无需手工改表，预览确认后导入）：

**① 班级报表《学生成绩.xlsx》**（指标）
- 版式：双行表头；首行含 `学号 / 考号 / 姓名 / 班级 / 英语`，次行为 `分数 / 班级排名 / 校内排名`
- 取数：「英语-分数」列 → 按**单板块「英语总分」**登记每人成绩
- 过滤：按文件中的班级列自动预选导入班级；班级/年级平均行自动跳过

**② 学科网《小题分_客观题在前（英语）.xlsx》**（指标）
- 版式特征：小题表头上一行能找到 `姓名 + 总分`；小题列头形如 `(1)`、`(1.5)`、`(2_A)` 等 `/\(\d+(\.\d+)?(_[A-Z])?\)/`
- 取数：客观题「答案列（`满分_字母`）」跳过、得分列保留；按大题行（一~十一，合并单元格向下填充）把小题得分汇总为**大题小分**（score=大题得分合计、max_score=大题满分合计）+ 每人总分
- 导入：在「导入小分」窗口同时写入总分与小分；在「导入成绩」窗口仅写总分

其余列格式（学号/姓名/班级/分数/题型…）按通用模板照常支持。

### 9.2 年级均分（grade_avgs）

- 指标口径：`{班级名: 平均分}`，值范围 0–满分；`null`/缺项 = 该班无官方数字，分析页自动用已录成绩计算（来源标注「自动计算」）
- 用途：考试「查看分析 → 🏫 年级均分」板块生成各班对比表、柱状图与本班年级名次/差距
- 迁移：选填；键必须是本空间当前学年已迁入的班级名

### 9.3 归档/结转/毕业/试用 对迁入数据的影响

| 机制 | 对迁入数据的影响 |
|---|---|
| 9 月 1 日学年初自动结转 | 非毕业班级（graduation_year 为空或未到）及其学生的 `academic_year` 自动更新为新学年；业务记录仍挂原学年，**不要手工改学年列** |
| 毕业归档 | `graduation_year` 等于新学年首位年份的班级，到点后**整体打包进毕业库并从主库删除**——这部分数据不再出现在平台，只有毕业包下载 |
| 10 月 1 日学年压缩归档 | 上一学年的默写/作业/考试明细被压缩，主表只留汇总（`archived_stats`）；明细只能从归档包离线解压 |
| 3 天试用 | 试用空间数据存独立试用库，到期物理删除，**不进入迁移/备份体系** |
| 回收站 | 删除记录保留 30 天可恢复，独立于备份体系 |

### 9.4 其余新字段速查

| 表 | 字段 | 迁移要点 |
|---|---|---|
| classes | `graduation_year` | 毕业年份（INTEGER），不毕业留空 |
| students | `exempt` | `1`=豁免作业/默写登记与统计，缺省 `0` |
| assignments | `pinned` / `target_ids` | `pinned=1` 置顶；`target_ids` 为指定学生 id 的 JSON 数组，NULL=全班 |
| dictations / exams | `archived_stats` | 系统写入，**导入留空** |
| exams | `grade_avgs` / `total_score` | `grade_avgs` 选填、键=班级名；`total_score` 为试卷总分，可空 |
| lessons | `content` | Markdown 正文（支持 LaTeX），可空 |
